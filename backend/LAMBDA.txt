Paper Plane Web — Backend: local HTTP and AWS Lambda

Runtime target: Node.js 24, ESM. No AWS resources are created by these commands.
Run commands from backend/.

Local development:
  npm ci
  npm run start:dev
Production HTTP:
  npm run build
  npm run start:prod
main.ts optionally loads the local .env file and listens on PORT (default 3000).
Lambda does not load .env or open a listening port.

Build Lambda artifact:
  npm run package:lambda
Output: build/lambda-<unique suffix>/ (ignored by Git).
The script uses npm ci --omit=dev --omit=optional --omit=peer --ignore-scripts
with the committed lockfile. Required runtime dependencies are declared directly;
optional Prisma CLI/TypeScript peers are excluded. The script rejects artifacts
at or above the 250 MiB uncompressed ZIP limit.
It copies only compiled backend, package manifests, and compiled game-math;
the generated Prisma client is included under backend/dist/generated/prisma.
The file: game-math dependency is materialized as a real directory, not a symlink.
Importing index.mjs is smoke-tested without connecting to PostgreSQL.
ZIP the CONTENTS of the output directory; index.mjs must be at archive root.
AWS handler: index.handler. Runtime: nodejs24.x.
For release, run packaging on Linux/Node.js 24 and validate the unpacked artifact.
Windows packaging is useful for local checks, not a substitute for that release check.
Do not copy .env, credentials, local node_modules, Prisma CLI or migration files into the runtime ZIP.
The script does not download RDS certificates: add an official public RDS CA bundle
to the artifact separately if using DATABASE_CA_FILE, or configure NODE_EXTRA_CA_CERTS.
Check ZIP and uncompressed sizes against Lambda limits before upload.

HTTP API integration:
Use payload format 2.0, routes ANY /{proxy+} and GET / (or a $default route).
The application expects /sessions, NOT /api/sessions. Strip /api at CloudFront
or configure the origin routing before forwarding. Disable API caching.
The handler supports JSON and base64 request bodies and reuses one initialization
promise across warm/concurrent invocations. Initialization failures return a sanitized
503 and can be retried by the next invocation. Do not automatically retry POST:
the request may have been persisted even if the response was lost.

Configuration (names and defaults only; provide secrets outside Git):
  DATABASE_URL                 required PostgreSQL URL; optional schema query parameter
  DATABASE_POOL_MAX            2; allowed 1..10
  DATABASE_CONNECT_TIMEOUT_MS  3000; allowed 1..30000
  DATABASE_IDLE_TIMEOUT_MS     10000; allowed 1..300000
  DATABASE_STATEMENT_TIMEOUT_MS 5000; allowed 1..30000 (server-side)
  DATABASE_QUERY_TIMEOUT_MS    6000; allowed 1..35000 (driver-side)
  DATABASE_SSL                disable locally; verify-full by default in Lambda
  DATABASE_CA_FILE            optional readable PEM certificate bundle path
  API_RATE_LIMIT              60 requests per IP per 60 seconds; allowed 1..1000
  PORT                        3000, local HTTP only
Lambda requires verify-full TLS; insecure verification bypass is not supported.
Do not combine URL ssl parameters with DATABASE_SSL: pg can override the explicit
TLS object. Configuration rejects this ambiguity. Use a trusted RDS CA and verify
the RDS hostname; never disable certificate checking to fix connection failures.
Prisma CLI migrations use DATABASE_URL independently of the runtime pool/TLS config;
configure verified TLS for the migration runner separately.

Resource lifecycle:
Local SIGTERM/SIGINT triggers Nest shutdown and Prisma disconnect (adapter ends pool).
Failed app initialization closes the app. Warm Lambda invocations retain the pool;
there is no per-request disconnect. AWS may freeze/terminate a runtime without hooks.
Idle timeout does not run while frozen: keep reserved concurrency small (initially 5),
leave connection headroom and monitor RDS connections. Increase limits only after tests.
Runtime needs only private RDS access; migration execution is a separate release job.

API protection and history:
429 with Retry-After is generated by @nestjs/throttler, shared across routes for an IP.
Counters are in-memory PER INSTANCE, not a global distributed rate limit. Configure
API Gateway stage/route throttling and Lambda reserved concurrency before publication.
Trust proxy is disabled. Lambda uses requestContext.http.sourceIp via serverless-http;
client-supplied X-Forwarded-For cannot change the counter key. Behind CloudFront this
may group users under proxy IPs; use WAF/edge limits if per-viewer limits are required.
Request JSON body limit: 8 KB. Oversized bodies return 413.
GET /sessions/:sessionId/attempts returns the latest 100 attempts, ordered by
createdAt ASC then id ASC. Array response shape is unchanged; older rows stay in DB.

Migrations (manual release step, NEVER Lambda startup):
  npm run db:migrate
Requires Prisma CLI/dev dependencies and separately authorized access to the target DB.
No migration or deployment was run while preparing this implementation.

Checks that do not access the database:
  node node_modules/typescript/bin/tsc --noEmit --incremental false
  npm run build
  npm test
  npm run package:lambda
  node --test ../shared/game-math/test/game-math.test.mjs
Tests use real Nest routes and HTTP adapter with Prisma mocked at its provider boundary.
The existing npm run test:e2e suite WRITES to PostgreSQL and cleans up its test rows.
Run it only against a dedicated disposable database after separate authorization.
Do not point it at real application data. It was not executed for this task.

Before deployment: verify Linux/Node24 artifact, RDS TLS connectivity, private subnets,
security groups, IAM least privilege, API Gateway limits, reserved concurrency,
log retention, backups, budget alerts, and cold/warm latency. No infrastructure is
provisioned here. Logging intentionally excludes raw errors, events and connection data.

REPEATABLE LINUX / NODE.JS 24 CHECK (no deployment)
Run from repository root with Docker Engine / Docker Desktop Linux containers:
  docker build --platform linux/amd64 -f backend/Dockerfile.lambda-check --target export --output type=local,dest=backend/build/linux .
This builds inside public.ecr.aws/lambda/nodejs:24 (Amazon Linux 2023), installs
dependencies using npm ci, compiles Prisma and game-math, and runs unit tests.
It creates a ZIP, validates CRC, root entrypoint, <50 MiB compressed and <250 MiB
uncompressed limits, then extracts that ZIP. A separate clean Lambda runtime stage
checks the extracted artifact, compiles/validates Prisma PostgreSQL WASM, and invokes
the actual handler (HTTP API v2, cold/warm root requests and 429).
The DB lifecycle is stubbed in that smoke test; it does NOT prove RDS connectivity,
SQL execution, TLS handshakes or cloud API Gateway integration. No migration runs.
The check targets x86_64 only; configure Lambda architecture x86_64 for this artifact.

Output:
  backend/build/linux/paper-plane-lambda.zip
  backend/build/linux/linux-check.txt (exported only after runtime checks succeed)
Docker build requires registry/npm network access, but no AWS account credentials.
.dockerignore excludes host dependencies, generated output and environment files.
No host Windows binaries or host node_modules are copied into the build image.
Runtime npm install disables bin links; artifact verification refuses all symlinks,
PE/ELF binaries and native .node modules. If native dependencies are added later,
review this policy explicitly instead of bypassing it.

For exact image reuse, pass --build-arg LAMBDA_IMAGE=public.ecr.aws/lambda/nodejs@sha256:<digest>.
The default :24 tag receives patches; this is a repeatable validation procedure,
not a promise of bit-for-bit identical output across changing base-image tags.
The lockfile pins npm dependencies; ZIP entry order, timestamps and modes are fixed.
GitHub workflow records the resolved image digest so the same base can be reused.
